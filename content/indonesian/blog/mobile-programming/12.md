## Arsitektur MVVM dan Room Database
Aplikasi ini dibangun dengan arsitektur MVVM (Model-View-ViewModel) yang merupakan rekomendasi resmi dari Google untuk pengembangan aplikasi Android modern. MVVM memisahkan kode menjadi tiga lapisan utama: View (tampilan UI), ViewModel (logika dan state), dan Model (data dan repository). Pemisahan ini membuat kode lebih rapi, mudah dirawat, dan dapat diuji secara terpisah.

Data user disimpan secara offline menggunakan **Room Database** yang merupakan abstraksi di atas SQLite. Room menggunakan tiga komponen utama: **Entity** (cetak biru tabel), **DAO** (kumpulan perintah SQL), dan **Database** (pintu masuk koneksi). Kombinasi MVVM + Room menjadi standar de-facto pengembangan Android saat ini.

<br>

## Entity dengan Anotasi @Entity dan @PrimaryKey
Class `User` merepresentasikan tabel `users` di database. Anotasi `@Entity(tableName = "users")` memberi tahu Room bahwa class ini adalah sebuah tabel, sedangkan `@PrimaryKey(autoGenerate = true)` menjadikan kolom `id` sebagai primary key yang nilainya bertambah otomatis setiap kali ada user baru.

Penggunaan `data class` membuat Kotlin secara otomatis menghasilkan fungsi `equals()`, `hashCode()`, `toString()`, dan `copy()` — sangat berguna saat memanipulasi objek user.

```java
@Entity(tableName = "users")
data class User(
    @PrimaryKey(autoGenerate = true)
    val id: Int = 0,
    val username: String,
    val password: String
)
```

<br>

## UserDao dengan Suspend Function
DAO (Data Access Object) adalah interface yang berisi semua perintah SQL untuk berinteraksi dengan tabel. Setiap fungsi diberi label `suspend` karena akses database harus dilakukan di background thread untuk menghindari UI freeze. Room akan otomatis membuat implementasi class-nya saat compile time, jadi kita cukup mendeklarasikan interface saja.

Anotasi `@Query` menerima string SQL biasa dengan dukungan parameter binding menggunakan format `:namaParameter`. Hasilnya `User?` (nullable) — jika tidak ada user yang cocok, akan mengembalikan `null` yang nanti digunakan untuk validasi login.

```java
@Dao
interface UserDao {
    @Insert(onConflict = OnConflictStrategy.IGNORE)
    suspend fun insertUser(user: User)

    @Query("SELECT * FROM users WHERE username = :username AND password = :password LIMIT 1")
    suspend fun login(username: String, password: String): User?

    @Query("SELECT COUNT(*) FROM users")
    suspend fun getUserCount(): Int
}
```

## AppDatabase dengan Singleton Pattern
`AppDatabase` adalah pintu masuk ke seluruh database Room. Class ini ditulis sebagai `abstract` karena Room yang akan men-generate implementasinya. Anotasi `@Database` menerima daftar entity dan nomor versi schema (dinaikkan setiap kali struktur tabel berubah).

Pattern **Singleton** dipakai supaya seluruh aplikasi hanya menggunakan satu instance database. Keyword `@Volatile` memastikan perubahan nilai `INSTANCE` langsung terlihat oleh semua thread, dan `synchronized(this)` mencegah dua thread membuat instance secara bersamaan.

```java
@Database(entities = [User::class], version = 1, exportSchema = false)
abstract class AppDatabase : RoomDatabase() {
    abstract fun userDao(): UserDao

    companion object {
        @Volatile
        private var INSTANCE: AppDatabase? = null

        fun getDatabase(context: Context): AppDatabase {
            return INSTANCE ?: synchronized(this) {
                val instance = Room.databaseBuilder(
                    context.applicationContext,
                    AppDatabase::class.java,
                    "login_app_database"
                ).build()
                INSTANCE = instance
                instance
            }
        }
    }
}
```

## UserRepository sebagai Perantara
Repository adalah lapisan abstraksi antara ViewModel dan sumber data (Room, API, dll). ViewModel tidak perlu tahu data datang dari mana — cukup memanggil Repository, dan Repository yang memutuskan apakah mengambil dari database lokal atau server. Pendekatan ini membuat kode mudah di-test dan fleksibel untuk perubahan sumber data.

Saat ini Repository hanya meneruskan panggilan ke DAO, tetapi struktur ini siap menampung logika tambahan seperti caching atau sinkronisasi dengan API server.

```java
class UserRepository(private val userDao: UserDao) {
    suspend fun login(username: String, password: String): User? =
        userDao.login(username, password)

    suspend fun insertUser(user: User) = userDao.insertUser(user)

    suspend fun getUserCount(): Int = userDao.getUserCount()
}
```

<br>

## Sealed Class untuk Mengelola State Login
`LoginState` adalah `sealed class` yang merepresentasikan semua kemungkinan keadaan layar login pada satu waktu: `Idle` (kondisi awal), `Loading` (sedang memproses), `Success` (berhasil), dan `Error` (gagal). Sealed class berbeda dengan enum karena setiap state dapat membawa data tambahan — misalnya `Success` membawa username, dan `Error` membawa pesan kesalahan.

Penggunaan sealed class membuat compiler bisa memverifikasi bahwa semua state sudah ditangani saat kita menulis blok `when`, sehingga lebih aman dari bug.

```java
sealed class LoginState {
    data object Idle : LoginState()
    data object Loading : LoginState()
    data class Success(val username: String) : LoginState()
    data class Error(val message: String) : LoginState()
}
```

## LoginViewModel dengan StateFlow dan viewModelScope
ViewModel adalah otak dari layar login. Kelas ini menyimpan state UI dalam bentuk `StateFlow` — sebuah holder data yang bersifat reactive. Setiap kali nilainya berubah, semua observer akan otomatis diberi tahu.

Pola yang dipakai adalah memisahkan `MutableStateFlow` (private, hanya bisa diubah dari dalam ViewModel) dengan `StateFlow` read-only yang diekspos ke UI. Ini disebut **encapsulation** — UI hanya boleh membaca state, tidak boleh mengubahnya langsung. Setiap operasi async dijalankan dalam `viewModelScope.launch { }` agar otomatis dibatalkan saat ViewModel di-destroy.

```java
class LoginViewModel(application: Application) : AndroidViewModel(application) {

    private val repository: UserRepository

    private val _loginState = MutableStateFlow<LoginState>(LoginState.Idle)
    val loginState: StateFlow<LoginState> = _loginState.asStateFlow()

    init {
        val userDao = AppDatabase.getDatabase(application).userDao()
        repository = UserRepository(userDao)
        seedDummyUser()
    }

    fun login(username: String, password: String) {
        viewModelScope.launch {
            _loginState.value = LoginState.Loading

            if (username.isBlank() || password.isBlank()) {
                _loginState.value = LoginState.Error("Username dan Password tidak boleh kosong")
                return@launch
            }

            val user = repository.login(username.trim(), password)
            _loginState.value = if (user != null) {
                LoginState.Success(user.username)
            } else {
                LoginState.Error("Username atau Password Salah")
            }
        }
    }
}
```

## Auto-Seed Data Dummy dengan init Block
Saat ViewModel pertama kali dibuat, kita perlu memastikan ada data user yang bisa dipakai untuk testing. Fungsi `seedDummyUser()` dipanggil di dalam `init` block — yang dijalankan otomatis saat ViewModel di-instansiasi. Fungsi ini memeriksa jumlah user di database; jika kosong, akan menambah user dummy `admin / 12345`.

Pengecekan jumlah dulu penting agar data dummy hanya disisipkan sekali, tidak setiap kali aplikasi dibuka.

```java
private fun seedDummyUser() {
    viewModelScope.launch {
        if (repository.getUserCount() == 0) {
            repository.insertUser(User(username = "admin", password = "12345"))
        }
    }
}
```

## State Hoisting untuk Preview Tanpa Database
LoginScreen dibagi menjadi dua fungsi composable: `LoginScreen` (stateful) yang terhubung ke ViewModel, dan `LoginScreenContent` (stateless) yang hanya menerima state lewat parameter. Pola ini disebut **state hoisting** dan merupakan best practice Compose.

Manfaatnya: `LoginScreenContent` dapat ditampilkan di Preview Android Studio tanpa membutuhkan ViewModel atau database. Cukup kirim state dan callback dummy, maka UI bisa dirender langsung di panel preview untuk berbagai keadaan (Idle, Success, Error).

```java
@Composable
fun LoginScreen(
    modifier: Modifier = Modifier,
    viewModel: LoginViewModel = viewModel()
) {
    val loginState by viewModel.loginState.collectAsState()

    LoginScreenContent(
        modifier = modifier,
        loginState = loginState,
        onLoginClick = viewModel::login,
        onInputChange = viewModel::resetState
    )
}

@Preview(showBackground = true, name = "Success")
@Composable
private fun LoginScreenSuccessPreview() {
    LoginPagePart2Theme {
        LoginScreenContent(
            loginState = LoginState.Success("admin"),
            onLoginClick = { _, _ -> },
            onInputChange = {}
        )
    }
}
```

## Observasi State dengan collectAsState
Untuk membuat UI Compose otomatis update ketika state di ViewModel berubah, kita gunakan `collectAsState()`. Fungsi ini mengubah `StateFlow` menjadi `State<T>` yang bisa dibaca Compose. Setiap kali nilai StateFlow berubah, Compose akan menjalankan **recomposition** — menggambar ulang bagian UI yang terdampak.

Inilah inti dari **reactive UI**: kita tidak perlu memanggil `setText()` atau `updateButton()` secara manual seperti di sistem UI lama. Cukup ubah state, dan UI mengikuti.

```java
val loginState by viewModel.loginState.collectAsState()

Button(
    onClick = { onLoginClick(username, password) },
    enabled = loginState !is LoginState.Loading
) {
    if (loginState is LoginState.Loading) {
        CircularProgressIndicator(color = Color.White)
    } else {
        Text("LOGIN", fontWeight = FontWeight.Bold)
    }
}
```

## StatusCard untuk Pesan Sukses dan Gagal
Komponen `StatusCard` adalah composable kustom untuk menampilkan kartu pesan dengan warna berbeda berdasarkan jenis pesan. Saat sukses, kartu berwarna hijau dengan ikon centang. Saat gagal, kartu berwarna merah dengan ikon peringatan. Pemilihan warna dilakukan dengan ekspresi `if` yang Kotlin-friendly.

Komponen ini dipanggil di dalam blok `when` yang membaca `loginState`, sehingga kartu hanya muncul saat state adalah `Success` atau `Error`.

```java
@Composable
private fun StatusCard(message: String, isSuccess: Boolean) {
    val bgColor = if (isSuccess) Color(0xFFD1FAE5) else Color(0xFFFEE2E2)
    val textColor = if (isSuccess) Color(0xFF065F46) else Color(0xFF991B1B)
    val icon = if (isSuccess) Icons.Default.CheckCircle else Icons.Default.Warning

    Card(
        modifier = Modifier.fillMaxWidth(),
        colors = CardDefaults.cardColors(containerColor = bgColor)
    ) {
        Column(modifier = Modifier.padding(16.dp)) {
            Icon(imageVector = icon, contentDescription = null, tint = textColor)
            Spacer(modifier = Modifier.height(8.dp))
            Text(text = message, color = textColor, fontWeight = FontWeight.Medium)
        }
    }
}

// Pemanggilan berdasarkan state
when (loginState) {
    is LoginState.Success -> StatusCard(
        message = "Login Berhasil! Selamat datang, ${loginState.username}",
        isSuccess = true
    )
    is LoginState.Error -> StatusCard(
        message = loginState.message,
        isSuccess = false
    )
    else -> Unit
}
```

## Penjelasan Setiap Lapisan
Tabel berikut merangkum peran dari setiap file Kotlin dan bagaimana mereka saling terhubung dalam alur MVVM. Aturan utamanya satu: data hanya boleh mengalir dari bawah ke atas (DAO → Repository → ViewModel → View), dan event mengalir dari atas ke bawah (View → ViewModel → Repository → DAO). Tidak ada shortcut.

| Lapisan | File | Tanggung Jawab |
|---------|------|----------------|
| **Model** | `User.kt` | Struktur data, definisi kolom tabel |
| **Model** | `UserDao.kt` | Perintah baca/tulis ke tabel `users` |
| **Model** | `AppDatabase.kt` | Konfigurasi koneksi Room (Singleton) |
| **Model** | `UserRepository.kt` | Abstraksi sumber data untuk ViewModel |
| **ViewModel** | `LoginViewModel.kt` | Menyimpan state UI, memproses login |
| **View** | `LoginScreen.kt` | Menggambar UI, mengirim event ke ViewModel |
| **Entry** | `MainActivity.kt` | Menyetel theme & Scaffold, memanggil LoginScreen |

<br>

## Filosofi Pemisahan `data/` dan `ui/`
Direktori `data/` dan `ui/` adalah dua "dunia" yang sengaja dipisahkan tegas. Kode di dalam `data/` tidak boleh tahu apa-apa tentang Compose, View, atau Android Framework (kecuali Context untuk Room). Sebaliknya, kode di dalam `ui/` tidak boleh menyentuh Room, DAO, atau SQL secara langsung — semuanya harus lewat ViewModel.

Manfaat praktis dari aturan ini: jika besok kamu memutuskan mengganti UI dari Jetpack Compose ke XML View, hanya isi folder `ui/` yang berubah. Sebaliknya, jika kamu mengganti penyimpanan dari Room ke API server, hanya isi folder `data/` yang terdampak. Lapisan ViewModel sebagai penghubung tetap utuh, sehingga pengembangan jadi jauh lebih aman dan terprediksi.

## Dependencies di build.gradle.kts
Untuk menjalankan aplikasi ini, beberapa library tambahan perlu ditambahkan ke `app/build.gradle.kts`. Plugin **KSP** (Kotlin Symbol Processing) dibutuhkan untuk meng-compile anotasi Room secara otomatis. Versi Room yang dipakai adalah 2.8.4 yang sudah kompatibel dengan Kotlin 2.x dan KSP2 versi terbaru.

```java
plugins {
    alias(libs.plugins.android.application)
    alias(libs.plugins.kotlin.android)
    alias(libs.plugins.ksp)
}

dependencies {
    // Room Database
    implementation("androidx.room:room-runtime:2.8.4")
    implementation("androidx.room:room-ktx:2.8.4")
    ksp("androidx.room:room-compiler:2.8.4")

    // ViewModel untuk Compose
    implementation("androidx.lifecycle:lifecycle-viewmodel-compose:2.9.4")

    // Icons extended
    implementation("androidx.compose.material:material-icons-extended")
}
```

## Langkah 1: Membuat Project Baru
Buka Android Studio dan pilih **New Project**, lalu pilih template **Empty Activity** yang sudah mendukung Jetpack Compose. Isi konfigurasi project dengan nama `LoginPagePart2`, package `com.example.loginpagepart2`, bahasa Kotlin, dan Minimum SDK API 24. Setelah klik **Finish**, tunggu hingga Gradle selesai melakukan sync — biasanya ditandai dengan hilangnya ikon loading di pojok kanan bawah Android Studio.

Android Studio akan otomatis menghasilkan file `MainActivity.kt` dengan composable `Greeting` bawaan dan folder `ui/theme` berisi tema default aplikasi. Tema ini akan tetap dipakai dan tidak perlu diubah.

## Langkah 2: Menambahkan Plugin KSP di Level Project
KSP (Kotlin Symbol Processing) adalah compiler yang dibutuhkan Room untuk meng-generate kode database secara otomatis. Buka file `build.gradle.kts` di level project (paling luar, bukan yang di dalam folder `app`), lalu tambahkan plugin KSP pada blok `plugins`. Versi KSP harus disesuaikan dengan versi Kotlin yang dipakai di project (cek di file `gradle/libs.versions.toml`).

```java
plugins {
    // ... baris yang sudah ada ...
    id("com.google.devtools.ksp") version "2.0.21-1.0.28" apply false
}
```

Daftar versi KSP yang kompatibel dengan setiap versi Kotlin bisa dilihat di halaman release resmi GitHub KSP.

## Langkah 12: Menjalankan dan Menguji Aplikasi
Hubungkan smartphone Android melalui kabel USB (pastikan opsi **USB Debugging** sudah diaktifkan di Developer Options) atau buka emulator melalui **Tools → Device Manager**. Klik tombol **Run** ▶ di toolbar atau tekan **Shift+F10** untuk meng-compile dan meng-install aplikasi ke device.

Setelah aplikasi terbuka, lakukan pengujian dengan beberapa skenario: login menggunakan kredensial yang benar `admin / 12345` akan menampilkan kartu hijau "Login Berhasil"; menggunakan password yang salah akan menampilkan kartu merah "Username atau Password Salah"; sedangkan ketika field input dibiarkan kosong akan menampilkan pesan validasi "Username dan Password tidak boleh kosong".

## Troubleshooting Masalah Umum
Bagian ini merangkum beberapa error yang sering muncul saat membuat aplikasi pertama kali dengan kombinasi Room + KSP, beserta cara mengatasinya. Sebagian besar error berakar pada ketidakcocokan versi antara Kotlin, KSP, dan Room Compiler — bukan kesalahan kode.

<br>

### Error "Using kotlin.sourceSets DSL is not allowed with built-in Kotlin"
Pesan error ini muncul karena Android Gradle Plugin (AGP) versi baru sudah mengelola Kotlin sendiri, sedangkan KSP masih mendaftar folder source-nya dengan cara lama. Solusinya cukup menambahkan satu baris pada file `gradle.properties` di root project lalu lakukan sync ulang. Ini adalah workaround resmi yang aman dipakai dan tidak memengaruhi fungsionalitas aplikasi.

```text
android.disallowKotlinSourceSets=false
```

<br>

### Error "[ksp] unexpected jvm signature V"
Error ini terjadi ketika versi Room Compiler tidak kompatibel dengan versi Kotlin atau KSP yang dipakai. Bug ini terjadi pada Room 2.6.x ketika dijalankan dengan Kotlin 2.x. Solusinya adalah meng-upgrade Room ke versi 2.8.4 atau yang lebih baru, sekaligus memastikan versi KSP sesuai dengan versi Kotlin pada `gradle/libs.versions.toml`. Setelah perubahan versi, lakukan **Build → Clean Project** lalu **File → Invalidate Caches and Restart** agar build cache yang lama benar-benar terhapus.

```java
import androidx.room.Dao
import androidx.room.Insert
import androidx.room.OnConflictStrategy
import androidx.room.Query
import com.example.loginpagepart2.data.local.entity.User

@Dao
interface UserDao {
    @Insert(onConflict = OnConflictStrategy.IGNORE)
    suspend fun insertUser(user: User)

    @Query("SELECT * FROM users WHERE username = :username AND password = :password LIMIT 1")
    suspend fun login(username: String, password: String): User?

    @Query("SELECT COUNT(*) FROM users")
    suspend fun getUserCount(): Int
}
```

```java
package com.example.loginpagepart2.data.local.database

import android.content.Context
import androidx.room.Database
import androidx.room.Room
import androidx.room.RoomDatabase
import com.example.loginpagepart2.data.local.dao.UserDao
import com.example.loginpagepart2.data.local.entity.User

@Database(entities = [User::class], version = 1, exportSchema = false)
abstract class AppDatabase : RoomDatabase() {

    abstract fun userDao(): UserDao

    companion object {
        @Volatile
        private var INSTANCE: AppDatabase? = null

        fun getDatabase(context: Context): AppDatabase {
            return INSTANCE ?: synchronized(this) {
                val instance = Room.databaseBuilder(
                    context.applicationContext,
                    AppDatabase::class.java,
                    "login_app_database"
                ).build()
                INSTANCE = instance
                instance
            }
        }
    }
}
```

### LoginViewModel.kt
```java
package com.example.loginpagepart2.ui.viewmodel

import android.app.Application
import androidx.lifecycle.AndroidViewModel
import androidx.lifecycle.viewModelScope
import com.example.loginpagepart2.data.local.database.AppDatabase
import com.example.loginpagepart2.data.local.entity.User
import com.example.loginpagepart2.data.repository.UserRepository
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.launch

sealed class LoginState {
    data object Idle : LoginState()
    data object Loading : LoginState()
    data class Success(val username: String) : LoginState()
    data class Error(val message: String) : LoginState()
}

class LoginViewModel(application: Application) : AndroidViewModel(application) {

    private val repository: UserRepository

    private val _loginState = MutableStateFlow<LoginState>(LoginState.Idle)
    val loginState: StateFlow<LoginState> = _loginState.asStateFlow()

    init {
        val userDao = AppDatabase.getDatabase(application).userDao()
        repository = UserRepository(userDao)
        seedDummyUser()
    }

    private fun seedDummyUser() {
        viewModelScope.launch {
            if (repository.getUserCount() == 0) {
                repository.insertUser(User(username = "admin", password = "12345"))
            }
        }
    }

    fun login(username: String, password: String) {
        viewModelScope.launch {
            _loginState.value = LoginState.Loading

            if (username.isBlank() || password.isBlank()) {
                _loginState.value = LoginState.Error("Username dan Password tidak boleh kosong")
                return@launch
            }

            val user = repository.login(username.trim(), password)
            _loginState.value = if (user != null) {
                LoginState.Success(user.username)
            } else {
                LoginState.Error("Username atau Password Salah")
            }
        }
    }

    fun resetState() {
        if (_loginState.value !is LoginState.Idle) {
            _loginState.value = LoginState.Idle
        }
    }
}
```

```java
@Composable
fun LoginScreen(
    modifier: Modifier = Modifier,
    viewModel: LoginViewModel = viewModel()
) {
    val loginState by viewModel.loginState.collectAsState()

    LoginScreenContent(
        modifier = modifier,
        loginState = loginState,
        onLoginClick = viewModel::login,
        onInputChange = viewModel::resetState

@Composable
fun LoginScreenContent(
    modifier: Modifier = Modifier,
    loginState: LoginState,
    onLoginClick: (String, String) -> Unit,
    onInputChange: () -> Unit
) {
    var username by remember { mutableStateOf("") }
    var password by remember { mutableStateOf("") }

    Surface(
        modifier = modifier.fillMaxSize(),
        color = MaterialTheme.colorScheme.background
    ) {
        Column(
            modifier = Modifier
                .fillMaxSize()
                .padding(24.dp),
            horizontalAlignment = Alignment.CenterHorizontally,
            verticalArrangement = Arrangement.Center
        ) {
            Surface(
                modifier = Modifier
                    .size(80.dp)
                    .clip(CircleShape),
                color = MaterialTheme.colorScheme.primary
            ) {
                Box(contentAlignment = Alignment.Center) {
                    Icon(
                        imageVector = Icons.Default.Person,
                        contentDescription = "User",
                        tint = Color.White,
                        modifier = Modifier.size(40.dp)
                    )
                }
            }

            Spacer(modifier = Modifier.height(16.dp))

            Text(text = "User Login", fontSize = 24.sp, fontWeight = FontWeight.Bold)
            Text(
                text = "Silakan masukkan username dan password",
                fontSize = 13.sp,
                color = MaterialTheme.colorScheme.onSurfaceVariant
            )

            Spacer(modifier = Modifier.height(28.dp))

            OutlinedTextField(
                value = username,
                onValueChange = {
                    username = it
                    onInputChange()
                },
                label = { Text("Username") },
                leadingIcon = { Icon(Icons.Default.Person, contentDescription = null) },
                singleLine = true,
                modifier = Modifier.fillMaxWidth()
            )

            Spacer(modifier = Modifier.height(16.dp))

            OutlinedTextField(
                value = password,
                onValueChange = {
                    password = it
                    onInputChange()
                },
                label = { Text("Password") },
                leadingIcon = { Icon(Icons.Default.Lock, contentDescription = null) },
                visualTransformation = PasswordVisualTransformation(),
                keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Password),
                singleLine = true,
                modifier = Modifier.fillMaxWidth()
            )

            Spacer(modifier = Modifier.height(24.dp))

            Button(
                onClick = { onLoginClick(username, password) },
                modifier = Modifier
                    .fillMaxWidth()
                    .height(50.dp),
                enabled = loginState !is LoginState.Loading
            ) {
                if (loginState is LoginState.Loading) {
                    CircularProgressIndicator(
                        color = Color.White,
                        modifier = Modifier.size(22.dp),
                        strokeWidth = 2.dp
                    )
                } else {
                    Text("LOGIN", fontWeight = FontWeight.Bold)
                }
            }

            Spacer(modifier = Modifier.height(20.dp))

            when (loginState) {
                is LoginState.Success -> StatusCard(
                    message = "Login Berhasil! Selamat datang, ${loginState.username}",
                    isSuccess = true
                )
                is LoginState.Error -> StatusCard(
                    message = loginState.message,
                    isSuccess = false
                )
                else -> Unit
            }

            Spacer(modifier = Modifier.height(20.dp))

            Text(
                text = "Contoh login: admin / 12345",
                fontSize = 12.sp,
                color = MaterialTheme.colorScheme.onSurfaceVariant
            )
        }
    }
}

@Composable
private fun StatusCard(message: String, isSuccess: Boolean) {
    val bgColor = if (isSuccess) Color(0xFFD1FAE5) else Color(0xFFFEE2E2)
    val textColor = if (isSuccess) Color(0xFF065F46) else Color(0xFF991B1B)
    val icon = if (isSuccess) Icons.Default.CheckCircle else Icons.Default.Warning

    Card(
        modifier = Modifier.fillMaxWidth(),
        colors = CardDefaults.cardColors(containerColor = bgColor)
    ) {
        Column(modifier = Modifier.padding(16.dp)) {
            Icon(
                imageVector = icon,
                contentDescription = null,
                tint = textColor,
                modifier = Modifier.size(28.dp)
            )
            Spacer(modifier = Modifier.height(8.dp))
            Text(text = message, color = textColor, fontWeight = FontWeight.Medium)
        }
    }
}
```
